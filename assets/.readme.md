# GCore Framework · `assets` 运行时资产包

`assets/` 是 Cocos Creator 扩展 **`gcore-framework`** 挂载到 AssetDB 的运行时资源目录，面向 **Cocos Creator 3.8.7+**。扩展通过 `package.json` 的 `contributions.asset-db.mount.path = "./assets"` 把本目录映射为 `db://gcore-framework/*`，因此这里的所有脚本、预制体既是编辑器资源，也是业务工程可直接 `import` 的运行时代码。

本文只介绍 `assets/` 目录（运行时框架）。编辑器扩展本体（面板、Luban 工具、字体子集化、IPC 消息等）见扩展根目录的 `README.zh-CN.md`。

本目录共 **68 个 TypeScript 脚本、2 个预制体、1 个 tsconfig**，按职责分为四层：

```text
assets/
├─ .readme.md                        # 本说明文档
├─ tsconfig.json                     # 资产包 TS 编译配置（target es2022 / strict / experimentalDecorators）
├─ gcore-console/                    # 【调试控制台】4 个脚本 + 2 个 prefab
│  ├─ gcore-console.prefab           # 控制台主界面（日志虚拟列表 / 输入框 / 候选指令 / 按钮）
│  ├─ gcore-console-log.prefab       # 单条日志项模板（可换行、可染色 Label）
│  └─ scripts/                       # 组件、视图、管理器、类型定义
└─ scripts/                          # 【框架运行时代码】64 个 .ts
   ├─ core-init.ts                   # 框架总入口组件 GCoreInit
   ├─ base/                          # 基础层：纯算法与数据结构（12 个 .ts，无业务耦合）
   │  ├─ container/                  # 委托、长整数、对象池、四叉树、随机队列
   │  └─ math/                       # 几何、PCG 随机、泊松盘采样、雪花 ID、UUID
   ├─ system/                        # 系统层：单例式基础设施（11 个 .ts）
   │  ├─ event/                      # 事件总线
   │  ├─ storage/                    # 本地存储 + 游戏配置
   │  ├─ fsm/                        # 状态机
   │  └─ debug/                      # 调试函数注册 + 测试用例框架
   └─ integration/                   # 集成层：与 Cocos 深度结合的业务模块（40 个 .ts）
      ├─ res/                        # 资源加载与引用计数
      ├─ mvc/                        # Model-View-Controller UI 架构
      ├─ audio/                      # 音频管理（BGM / SFX / 音量）
      ├─ i18n/                       # 多语言运行时 + 编辑器预览
      └─ ui/                         # UI 组件库（19 个 .ts）
```

## 一、引入方式

### 1. 推荐：`db://gcore-framework/*`（项目实际使用）

Cocos 生成的 `temp/tsconfig.cocos.json` 中已配置路径映射：

```text
db://gcore-framework/*  ->  <项目>/extensions/gcore-framework/assets/*
```

业务代码中的真实示例（`assets/script/gaming/fight/HeroController.ts`）：

```ts
// 从 UI 组件库桶文件引入虚拟列表以外的预制体列表组件
import { PrefabList } from 'db://gcore-framework/scripts/integration/ui';
```

### 2. 包级子路径：`gcore-framework/<subpath>`

扩展 `package.json` 的 `exports` 声明了以下 12 个子路径，均指向对应 `index.ts` 桶文件：

| 子路径 | 指向 |
| :--- | :--- |
| `gcore-framework/base/container` | `scripts/base/container/index.ts` |
| `gcore-framework/base/math` | `scripts/base/math/index.ts` |
| `gcore-framework/system/event` | `scripts/system/event/index.ts` |
| `gcore-framework/system/storage` | `scripts/system/storage/index.ts` |
| `gcore-framework/system/fsm` | `scripts/system/fsm/index.ts` |
| `gcore-framework/system/debug` | `scripts/system/debug/index.ts` |
| `gcore-framework/integration/res` | `scripts/integration/res/index.ts` |
| `gcore-framework/integration/mvc` | `scripts/integration/mvc/index.ts` |
| `gcore-framework/integration/ui` | `scripts/integration/ui/index.ts` |
| `gcore-framework/integration/i18n` | `scripts/integration/i18n/index.ts` |

| `gcore-framework/integration/core-init` | 声明指向 `scripts/integration/core-init.ts`（见「已知边界」） |

> **注意**：音频模块文档里的示例写作 `gcore-framework/audio`，MVC 文档里的示例写作 `from "gcore"`，这两者当前**没有**对应的 `exports` / `paths` 配置；工程内可用且已验证的是 `db://gcore-framework/...` 形式。

## 二、框架初始化：`GCoreInit`

文件：`scripts/core-init.ts`。挂载到启动场景任意节点，`onLoad()` 即完成全部单例初始化，并在最后触发「游戏开始函数」，业务层无需手动逐个 `init()`。

### 挂载属性

| 属性 | 类型 | 说明 |
| :--- | :--- | :--- |
| `root` | `Node` | UI 根节点，作为所有界面的父节点（MVC / 音频宿主） |
| `mainCanvas` | `Canvas` | 主 UI 画布，用于自适应屏幕大小（当前 `_init()` 未直接使用） |
| `gameHandler` | `EventHandler` | 游戏开始回调；刻意不用生命周期函数，避免初始化顺序错误 |

### 初始化顺序

```ts
// scripts/core-init.ts 的 _init() 流程（按顺序执行）
EventTarget.isValidChecker = isValid;   // 注入节点有效性校验，解除事件模块对 cc 的物理依赖
gcoreStorage.init();                    // 本地存储
gcoreRes.init();                        // 资源管理器
gcoreConfig.init();                     // 游戏配置（异步预热缓存，未 await）
gcoreAudio.init({                       // 音频：注入宿主节点与 AudioClip 加载/释放委托
    root,
    loadClipFunc,                        // -> gcoreRes.loadRes<AudioClip>(path, bundle)
    releaseClipFunc                      // -> gcoreRes.releaseRes(path, bundle)
});
gcoreMvc.init({                         // MVC：注入 UI 根节点与 Prefab 加载/释放委托
    root,
    viewPrefabFunc,                      // -> gcoreRes.loadRes<Prefab>(prefab, pack)
    viewPrefabReleaseFunc                // -> gcoreRes.releaseRes(prefab, pack)
});
EventHandler.emitEvents([gameHandler], null);  // 通知业务「框架已就绪」
```

### 全局单例速查

> 下列「全局单例」均为 **模块级 `export const` 单例**，不是 `window.*` / `globalThis.*` 属性。

| 单例 | 所在模块 | 职责 | 初始化方式 |
| :--- | :--- | :--- | :--- |
| `gcoreStorage` | `system/storage` | 分层本地存储 | `GCoreInit` 自动 |
| `gcoreConfig` | `system/storage` | 游戏配置快照 | `GCoreInit` 自动 |
| `gcoreRes` | `integration/res` | 资源加载 / 引用计数 / 缓存 | `GCoreInit` 自动 |
| `gcoreAudio` | `integration/audio` | 背景音乐与音效 | `GCoreInit` 自动 |
| `gcoreMvc` | `integration/mvc` | 界面注册 / 打开 / 关闭 | `GCoreInit` 自动 |
| `gcoreEvent` | `system/event` | 全局事件总线 | 无需 init，仅注入 `isValidChecker` |
| `gcoreGfs` | `system/fsm` | 流程状态机 | 无 init，业务自行 `register()` |
| `i18n` / `gcoreI18n` | `integration/i18n` | 多语言（同一实例的两个名字） | 无 init，调用 `switchLanguageFromXxx()` |
| `gcoreConsole` | `gcore-console` | 运行时调试控制台 | `GCoreConsole` 组件 / 视图兜底 `init()` |
| `gdebug` | `system/debug` | 调试函数注册表 | 模块加载时自动 `initDebug()` |

## 三、功能清单（按模块）

### 3.1 `scripts/core-init.ts` — 框架总入口

- `GCoreInit` 组件（`@ccclass("GCoreInit")`、`@menu("GCore/GCoreInit")`）。
- 统一装配顺序、注入依赖（资源加载委托、UI 根节点）、回调业务启动逻辑。

### 3.2 `base/container` — 数据结构（纯 TS，无 Cocos 依赖）

`index.ts` 统一导出：`Delegate`、`DelegateHandler`、`Long`、`Pool`、`IRect`、`Rect`、`Quadtree`、`RandomQueue`、`RandomQueueSnapshot`。

| 文件 | 功能要点 |
| :--- | :--- |
| `delegate.ts` | 泛型多播委托 `Delegate<TArgs, TResult>`：`plus / minus / has / once / invoke / clear / destroy`；`invoke` 返回最后一个处理器结果；调用期内增删监听器安全（延迟删除 + 原地压缩）；支持 `thisArg` 绑定 |
| `long.ts` | 无符号 64 位整数 `Long`（高低两个 uint32），不可变运算：`fromNumber / fromString / add / multiply / and / or / xor / shiftLeft / shiftRightUnsigned / toNumber / equals / greaterThan`；`toNumber()` 只返回低 32 位 |
| `pool.ts` | 泛型对象池 `Pool<T>`：`initSize` 预热、`growSize` 批量扩容、`maxSize` 硬上限溢出交 GC、`alloc / free / clear / size`；`free` 不重置对象状态（需外部处理） |
| `quadtree.ts` | 泛型四叉树 `Quadtree<T>` + `Rect / IRect`：默认容量 40、最大深度 3，`insert / retrieve / clear / totalObjects`；仅完全落入单一象限的对象才下推；边界严格相交判定（相接不算相交） |
| `random-queue.ts` | 不放回随机队列 `RandomQueue`：位掩码池（m∈[0,1023]，m=1023 仅 128 字节），**rank 选择法** `O(⌈m/32⌉)` 无拒绝采样；`next()` 支持条件过滤（被拒绝的值自动放回）、自动重置；`recover(snapshot)` 支持存档恢复；可共享同一 `PcgRandom` 实例 |

### 3.3 `base/math` — 数学与随机算法

`index.ts` 统一导出：`UuidV4`、`Uid10Bit`、`Line2D`、`MathUtil`、`PcgRandom`、`PoissonDisk`、`SnowflakeIdNumber`、`SnowflakeId`。

| 文件 | 功能要点 |
| :--- | :--- |
| `create-uiid.ts` | `UuidV4()` 生成 v4 UUID 字符串；`Uid10Bit()` 生成 10 位 `A-Za-z0-9` 短 ID；基于 `Math.random()`，不可种子复现 |
| `math.ts` | `Line2D`（斜截式、`fromPoints`、`getY`，垂直线返回 `null`）；`MathUtil` 静态几何工具：`intersects`（AABB）、`isPointInRect`、`getPolygonBounds`、`isPointInPolygon`（射线法） |
| `pcg-random.ts` | 标准 **PCG-XSH-RR** 伪随机 `PcgRandom`：可种子复现、可指定 `streamId`；`getUint32 / getIntRange(min,max)`（**左闭右开**）、`getFloat / getFloatRange`、`getWeight`（轮盘赌返回下标）、`jump(steps)`（O(log n) 跳步）、`setGenerateCallback`、`getUuidv4()`；依赖 `Long` 实现 64 位 LCG |
| `poisson-disk.ts` | 泊松盘采样 `PoissonDisk`：`PoissonDiskSampling()` 支持矩形区域、四条 `Line2D` 围成的凸四边形区域、按数量取子集；`PoissonDiskSamplingDense()` 多次重试取最密一批；核心为 **Bridson 算法**（K=30、网格加速）+ Andrew Monotone Chain 凸包 + Fisher-Yates 洗牌 |
| `snow-flake.ts` | 雪花 ID `SnowflakeIdNumber(): number` / `SnowflakeId(): string`：秒级时间戳（epoch 2020-01-01）、10 位节点 ID、12 位序列号，趋势递增且保证落在 `Number.MAX_SAFE_INTEGER` 内；时钟回拨钳制等待 |

### 3.4 `system/event` — 事件总线

`index.ts` 导出 `EventTarget`、`GCoreEvent`、`gcoreEvent`。

- `EventTarget`：`on / once / off / targetOff / emit / hasEventListener / cleanInvalidListeners`；`type` 支持 `string | number`。
- **依赖注入解耦**：静态 `EventTarget.isValidChecker` 由 `GCoreInit` 注入 Cocos `isValid`，失效监听在 `emit` 时自动清理，无需手动 `off`。
- `emit` 使用监听器副本派发，保证回调内增删监听不破坏遍历；`once` 在调用前移除。
- `GCoreEvent` 预置框架事件常量：`MVC_EVENT`（`REGISTER_VIEW / OPEN_VIEW / CLOSE_VIEW`）、`RES_LOAD_EVENT.BUNDLE_LOAD_COMPLETE`、`LANGUAGE_CHANGED.SWITCH_LANGUAGE`、`FSM_EVENT.ENTER / EXIT`。

### 3.5 `system/storage` — 本地存储与游戏配置

`index.ts` 导出 `StorageMgr`、`gcoreStorage`、`ConfigMgr`、`gcoreConfig`。

| 文件 | 功能要点 |
| :--- | :--- |
| `storage-mgr.ts` | `StorageMgr` 基于 `sys.localStorage` 的 JSON 存取：`setUserId()` 划分用户域；分层 key（`global_xxx` / `user_<id>_xxx` / `user_default_xxx`）；API `set / get / save / load / remove / clear`；`clear` 按前缀清理（仅浏览器平台生效）；**无加密** |
| `config-mgr.ts` | `ConfigMgr` 管理单个整体游戏配置对象：`init()` 预热缓存、`getGameConfig()`、`saveGameConfig()`、`updateGameConfig(partial)` 浅合并、`clearGameConfig()`；双写持久化（`global_GAME_CONFIG_KEY` 与裸 `GAME_CONFIG_KEY`）并兼容旧数据回退 |

### 3.6 `system/fsm` — 流程状态机

`index.ts` 导出 `BaseFsm`、`FsmMgr`、`gcoreGfs`。

- `BaseFsm`：状态基类，只读 `state`、`onInit(state)`、异步钩子 `onEnter()` / `onExit()`（子类覆盖）。
- `FsmMgr`：`register(type, ctor)` 注册状态、`enter(type)` 切换（先 `await onExit()` → 发 `FSM_EVENT.EXIT` → 新实例 `onInit/onEnter` → 发 `FSM_EVENT.ENTER`）；单一当前状态、无历史栈、无并发切换保护。

### 3.7 `system/debug` — 调试与测试框架

`index.ts` 导出 `gdebug`、`GDebugCase`。

| 文件 | 功能要点 |
| :--- | :--- |
| `gdebug.ts` | DEBUG 下向 `window.game` / `window.debug` 注入调试环境；`addTouchDebug2D(node, camera, func?)` 打印点击的世界/本地坐标；`addDebugFunc(key, func)` 注册调试函数；`addDebugDecorator(key?)` 方法装饰器注册；浏览器控制台直接 `window.debug.xxx()` 调用 |
| `gdebug-case.ts` | 装饰器式测试用例框架 `GDebugCase`：`@GCoreTestCase("别名")`、`@GCoreTestFunc()`、`@GCoreTestAsyncFunc()`；生成 `globalThis[别名]()` 全量运行入口与 `globalThis[别名].方法名()` 单方法入口；深比较期望值、统计 通过/失败/异常、`isErrorEnd` 遇错即停 |

### 3.8 `integration/res` — 资源加载与引用计数

`index.ts` 导出 `EResBundlePolicy`、`ResLoadMgrInitOptions`、`ResLoadMgr`、`gcoreRes`。

- `EResBundlePolicy` 三种 bundle 策略：
  - **Core**：`loadDir("")` 全量 `addRef()` 常驻固定，业务 `releaseRes` 不动常驻引用，仅 `releaseBundle` 统一释放。
  - **Hot**：引用归零不 `decRef()`，进入跨 bundle 共享的 LRU 热缓存（`hotCacheCapacity` 控制容量，0 时行为接近 Normal），再次加载直接复活引用。
  - **Normal**：引用归零即 `decRef()` 并从映射移除。
- 核心 API：`init({hotCacheCapacity})`、`loadBundle(pack, policy)`（并发去重、完成后发 `BUNDLE_LOAD_COMPLETE`）、`releaseBundle`、`loadRes<T>(path, pack)`、`retainRes / releaseRes / releaseAssets`、`setSprite / setSpriteFormAtlas / releaseAssetsFormAtlas`。
- 引用计数 key 为 `` `${packName}:${resPath}` ``，`managedRef` 标记避免与 Core 常驻引用失衡；`setSprite` 用 `WeakMap` 防异步旧请求覆盖新请求，并在替换时自动释放旧 Sprite 引用。

### 3.9 `integration/mvc` — UI 架构

`index.ts` 导出 `BaseModel`、`BaseView`、`BaseCtrl`、`MvcMgr`、`gcoreMvc`，以及 `IView / IViewParams / IViewParamMap / IViewHandle / IMvcParams / IViewAttribute / IMvcMrgParams / ViewType / ViewId / ViewOpenArgs`。

| 文件 | 功能要点 |
| :--- | :--- |
| `base-model.ts` | 数据层基类 `BaseModel`：`tid`、`onInit / onDestroy`；每个 `tid` 常驻唯一 Model，多实例 View 共享 |
| `base-ctrl.ts` | 控制层基类 `BaseCtrl`：`tid`、`data`（注入的 Model）、`onInit / onDestroy`；不持有 View |
| `base-view.ts` | 视图层基类 `BaseView<P> extends BaseUi`：`onInit(tid, iid, ctrl, model, params)`、`onOpen()`、`onShow()`、`getTid / getIid`、`close()`；关闭走静态函数指针 `CloseFunc`（由 `MvcMgr.init` 绑定），避免每个 View 注册事件 |
| `mvc-interface.ts` | 类型安全核心：`ViewOpenArgs<P>` 让 `open()` 的第二个参数按 `IViewParamMap` 编译期推导（业务用 `declare module` 扩展）；`IViewHandle { tid, iid, close() }`；`IViewAttribute { priority, bIsOnly, bResident, bIsdaptation }` |
| `mvc-mgr.ts` | `MvcMgr`：`init(params)`、`register / registerAll`、`open<K>(tid, ...args): Promise<IViewHandle>`、`close / closeAll`、`getView / getViews / getModel / getCtrl`；五张映射表 + 自增 `iid` 支持多实例；**单实例/常驻视图复用**（`onShow`）、并发 `open` 去重、`bIsdaptation` 屏幕尺寸自适应并监听 `window-resize`；注册/打开/关闭均发 `MVC_EVENT` |

> 详见 `integration/mvc/README.md`（含 `UiDefine` 注册示例、`IViewParamMap` 扩展写法）。

### 3.10 `integration/audio` — 音频管理

`index.ts` 导出 `AudioMgr / gcoreAudio`、`AudioConfig`、`MusicChannel`、`EffectChannel`、`AudioButton` 与全部类型契约。

- **架构**：`gcoreAudio` 门面 = `AudioConfig`（音量/静音计算）+ `MusicChannel`（BGM）+ `EffectChannel`（SFX）。
- **BGM**：双 `AudioSource` 轨道 CrossFade 淡入淡出；音乐栈 `pushMusic / popMusic` 临时插播并平滑恢复；支持路径或 `AudioClip` 实例；`_playSerial` 防并发加载乱序。
- **SFX**：`AudioSource` 对象池（默认预热 8）、`ENDED` + 定时器双兜底回收、50ms 同名防连击节流、同名并发上限 4 / 总活跃上限 32、`audioId` 句柄可单独调音量或停止。
- **音量**：`主音量 × 分组音量 × 实例相对音量`；`setConfig / getConfig` 快照与业务存档解耦；`pauseAll / resumeAll`。
- **平台自适应**：监听 `Game.EVENT_HIDE / EVENT_SHOW`，切后台自动暂停、切回前台只恢复原本在播放的内容。
- **零代码组件**：`AudioButton` 挂到带 `Button` 的节点即可配置点击音效。
- `GCoreInit` 自动注入 `root` 与基于 `gcoreRes` 的加载/释放委托。

> 完整 API 速查表见 `integration/audio/.readme.md`。

### 3.11 `integration/i18n` — 多语言

`index.ts` 导出 `I18nMgr`、`i18n` / `gcoreI18n`、`I18nLabel`、`I18nRichText`。

| 文件 | 功能要点 |
| :--- | :--- |
| `i18n-mgr.ts` | `I18nMgr`：`parseBinary / parseBufferAsset` 解析 Luban 二进制语言包；`switchLanguageFromData / FromBuffer / FromBufferAsset / FromBinary / FromJson` 多形态注入；`getText(key, fallback)`、`has(key)`、`clear()`；切换时发 `LANGUAGE_CHANGED.SWITCH_LANGUAGE`；编辑器下读 `design/配置/多语言/配置/*.csv` + `temp/gcore-lang-state.json` 做 500ms 轮询实时预览，预览文本通过 `Editor.Message.request('gcore-framework', 'query-i18n-text', ...)` 查询 |
| `base/ByteBuf.ts` | Luban 解码器（默认导出 `ByteBuf`）：Varint 前缀编码的 `readInt / readLong / readSize / readString`，以及 bool/byte/short/float/double/bytes/arrayBuffer 等；配套 `EDeserializeError` |
| `components/i18n-label.ts` | `I18nLabel`（`@executeInEditMode`）：`i18nKey / fallback / params / label / selectKey`、`setKey()`、`refresh()`；`onEnable/onDisable` 订阅语言切换；`{0}{1}` 占位符格式化；编辑器双阶段（同步缓存 + IPC 异步）刷新 |
| `components/i18n-rich-text.ts` | `I18nRichText`：与 Label 同构，作用于 `RichText`，支持富文本标签的多语言刷新 |

**`VScrollView` 提供的能力：**

- **槽位复用**：只创建「一屏 + `buffer`」个槽位，滚动时循环搬运槽位并重新绑定数据索引；跳跃或强制刷新才整段重排。
- **多类型 / 不等高**：`getItemTypeIndexFn` 多类型对象池分池复用；`getItemHeightFn` + 前缀和 `_prefixPositions` + 二分查找支持动态 item 尺寸，尺寸变更增量重建。
- **布局**：`gridCount / gridSpacing / spacing / headerSpacing / footerSpacing / autoCenter`（内容不足一屏居中）、`useVirtualList` 可退化为普通滚动容器。
- **物理滚动**：惯性速度采样（末 5 帧平均）、指数衰减 / iOS 分段减速曲线、`springK / springC` 越界回弹、`pixelAlign` 像素对齐、`disableBounce` 硬限制；全局 `TOUCH_END/CANCEL` 兜底防状态卡死；嵌套滚动按 ±30° 角度拦截方向。
- **下拉刷新 / 上拉加载**：越界阻尼 + `IDLE→PULLING→READY→REFRESHING/LOADING→COMPLETE/NO_MORE` 状态机，外部通过 `finishRefresh() / finishLoadMore()` 收尾。
- **分页吸附**：按拖动比例或速度阈值触发，tween 到最近页，`onPageChangeFn` 通知。
- **异步节点供给**：`provideNodeFn(index)` 支持返回 `Promise<Node>`。
- **公共 API**：`refreshList / setTotalCount / refreshIndex / updateItemHeight(s) / scrollToTop / scrollToBottom / scrollToIndex / flashToTop / flashToBottom / flashToIndex / scrollToPage / getCurrentPageIndex / finishRefresh / finishLoadMore / resetLoadMoreState / onOffSortLayer`。
- **item 交互**：自动 `addComponent(VScrollViewItem)` 注入点击/长按回调，新增数据索引进入可视区时播放 `playItemAppearAnimationFn`。

## 五、使用须知与已知边界

1. **桶文件未导出的符号**：`PolygonBtn`（`ui`）、`ByteBuf` 默认导出（`i18n/base`）、`I18nEditorUtil`（`i18n/editor`）需按相对/子路径单独 `import`。
2. **`create-uiid.ts` 在 `base/math/` 下**，由 `base/math/index.ts` 导出，不在 `base/container` 中。
3. **源码拼写**（请勿「纠正」，按原样引用）：`EAddaptType`、`bIsdaptation`、`longPressinterval`、`setSpriteFormAtlas`、`releaseAssetsFormAtlas`、文件名 `gocre-console-mgr.ts`。
4. **区间与精度**：`PcgRandom.getIntRange(min, max)` 为**左闭右开**；`Long.toNumber()` 只返回低 32 位；`SnowflakeId` 明确不保证 64 位整数完全精确。
5. **单例不是 `window` 全局**：`gcoreXxx` 均为模块 `export const`，必须 `import`；只有 `window.game / window.debug`（gdebug）与 `globalThis[别名]`（GDebugCase）是运行时全局注入。
6. **无统一销毁接口**：`system/*` 多数单例没有 `destroy()`；提供 `destroy()` 的只有 `gcoreAudio` 与 `gcoreConsole`（以及部分 UI 组件的 `onDestroy` 清理）。
7. **MVC 实现与文档差异**：`IMvcParams.layer`、`IViewAttribute.priority`、`IViewParams.onClose`、`close(destroy?)` 的 `destroy` 形参、`viewPrefabReleaseFunc` 目前均**未被 `MvcMgr` 读取/调用**；所有视图统一 `setParent(root)`，预制体资源释放需业务自行处理。另 `mvc/README.md` 中 `onRefresh()` / 参数顺序等示例与源码（`onShow()`、`close(tid, iid?, destroy?)`）不一致，**以源码为准**。
8. **res 文档注释差异**：`res-load-mgr.ts` 尾部注释示例中的 `setBundlePolicy`（实际为 `private`）、`clearHotCache / getResRefCount / getHotCacheSize` 等**未实现**；bundle 策略只能在 `loadBundle(pack, policy)` 时指定。
9. **i18n 事件参数**：`LANGUAGE_CHANGED.SWITCH_LANGUAGE` 常量注释写「无参数」，实际 `I18nMgr._sendEvent()` 会带上当前语言字符串。
10. **别名配置**：`package.json` 的 `./integration/core-init` 指向 `scripts/integration/core-init.ts`，而实际文件位于 `scripts/core-init.ts`；`gcore-framework/audio` 与 `from "gcore"` 的文档示例当前无对应映射，建议使用 `db://gcore-framework/...`。
11. **控制台范围**：`gcoreConsole` 提供通用命令注册（可用于 GM 指令），但**内置指令仅 `help / clear / cls / echo / history`**；无内置 GM 命令、无日志级别过滤 UI、无触摸手势唤起、无日志本地持久化（"持久化"指跨场景常驻宿主节点）。项目业务层的 `assets/script/gm/GMPanel.ts` 是另一套独立 GM 面板。
